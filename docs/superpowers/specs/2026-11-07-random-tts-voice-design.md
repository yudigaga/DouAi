# 每次合成随机音色

2026-11-07 用户已确认采用每次合成自动随机，并审阅同意本方案的“关闭／小随机／大随机”三档交互和单音色限制。

## 使用方式

在“文本转语音设置”的“语音来源”下增加“随机音色”。默认关闭，旧配置继续使用手动选择的来源和音色。

| 模式 | 每次新合成的行为 |
| --- | --- |
| 关闭 | 使用已保存的来源和音色 |
| 小随机 | 仅从当前来源的有效音色列表随机选择 |
| 大随机 | 先等概率选择已配置且有有效音色的来源，再随机选择该来源的音色 |

大随机的范围包含系统引擎、第三方、MiniMax、Breeze Blue 和 Fish Audio。系统引擎限当前引擎提供的、匹配配置语言的离线音色；网络来源限已加载的目录，不在每次合成时额外查询所有来源。普通随机允许连续抽到相同来源或音色。

网络来源需要先在设置中刷新音色。密钥或必要配置不完整、列表为空、目录与当前账户/地址/筛选条件不符的来源不参加大随机。小随机遇到不可用配置或空目录时明确提示，不假装已经随机。只有一个可用来源时，大随机在该来源内抽取。

MiniMax 混音及 Fish 多说话人/参考音频模式与选择单个音色不兼容：小随机提示先改为单音色；大随机排除这些来源。用户已审阅同意该限制。

## 实现方案

在所有语音入口共享的 `SpeechSynthesis.synthesize` 创建请求内随机选择，系统音色在 `LocalSpeechSynthesis` 初始化引擎后选择。配置使用不可变请求快照，不覆盖手动保存的来源、音色或高级参数。选定来源后保持现有合成、取消、超时和错误处理。

设置试听、手动评论/私信、自动评论、评论回复和私聊/群聊回复共用此逻辑。发布重试继续复用已生成的音频；不新增合成重发或跨来源失败转移。

保留仍有效的跨来源音色目录，并继续验证账户、地址和筛选标记。试听快照必须包含随机模式、各来源目录和目录标记。第三方列表继续使用原样 GET 与请求头；合成 GET 必须使用 `{voice}` 才能参与随机。

## 方案取舍

已选择每次合成自动抽取，而不是按钮换一次后固定使用。采用共用合成入口，避免各调用点重复实现并漏掉试听或手动功能。大随机采用先抽来源再抽音色，避免目录数量影响来源概率。

本次不增加权重、去重历史、自动加载完整远端目录、混音随机组合或独立随机池编辑器。现有语速、音调、模型、音频格式、正文和语音失败后的文本回退规则继续由各来源与入口控制。

## 验证

验证随机边界、来源资格、空目录/失配缓存、单音色限制、请求快照隔离、关闭模式兼容，以及试听与设置持久化。回归共享合成与语音准备测试，并执行 Release lint。真实设备引擎、远端账号合成和抖音发布需要实测，不能由本地测试替代。
