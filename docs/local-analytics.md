## 侧写升级（0.2.62 起）

报告先展示「这段时间的发现」，再按「遇见了什么」「什么让我动手」「与上期相比」阅读；「查看全部统计」保留原日历、作者/话题排行、最近记录和使用历程。无模型也能查看本地发现。新界面与导出的图形来自同一份快照；下面的历史说明保留既有统计口径。

- **话题持续性**：从完整逐日话题统计选择展示项，同时看次数、出现浏览日数、峰值日份额和当天含此话题的浏览占比。多话题比例不相加，缺记录日期不作零使用。
- **同片段主动操作**：分别比较保存入口、复制成功；一次片段重复操作只记一次阳性。n/N 是发生过指定操作的保留片段数/该组保留片段数，不是用户数、操作成功率或喜欢程度。无标签片段、空令牌及已裁剪关系不进入话题对照。
- **两期变化分解**：使用实际标注的相邻完整七日窗口，把记录率变化拆为作品类型构成及类型内记录率变化，单位是百分点。样本不足、采集关闭、来源起点未知或明细截断时只并列记录；不作因果归因。
- **探索路径**：只显示已记录阶段及真实相邻路径的会话数；生成、派发、实际追问/卡片点击与路由派发分开。不能确认推荐可见时不给曝光转化率，路由返回不代表开始播放。
- **近期重逢**：此前28天作品日有记录才识别为近期遇见过；历史不充分保持未知。同作品日选第一个合格的自然切换结束片段，在同类型/到达来源内比较可见时长中位数与中间一半范围。恢复备份、未结束和其他截断会排除；可见时长不等于注视或完播，未知到达来源不叫手动。

新增采集保留作者匿名键、作品时长档、图片张数档和广告三态；老记录的新增字段保持未知。播放器状态、真实回划、手动倍速/继承/读回及下载过程按已支持入口记录。操作号在发起时冻结代次和原片段，迟到完成不会借用后来作品；一次操作可含多个任务。「输出关闭」表示本模块流写入并关闭的证据，不表示重新读取文件验收。

按日汇总仍最多365天，片段及动作明细最多30天；访问最多20,000段，旧动作与新流程事件合计最多30,000条。范围更长时，动作章节注明实际明细范围。SQLite升级为v3；可选分析备份独立为v2并能读旧v1，恢复不打开采集。旧库/旧备份不回填覆盖水位，新版明确记录本地接收链起点、裁剪和已知缺口，不能据此宣称覆盖宿主全部页面。

主动请求AI时优先发送至多三条精选证据，附范围、n/N、单位、比较与局限。新版返回基于证据ID的文字；测量数字由本地插入。未知证据、重复证据及未经核对的数量/比例措辞回退本地依据；结构或传输错误沿用错误及重试流程。全局与二级提示词仍受保留，不自动请求。额外自述始终是本人说明，反馈不作为行为事实。

本轮不包含性格问卷或人格分。验证范围与设备边界见[0.2.64 发布记录](release-0.2.64.md)。

0.1.81 在本页基础上增加融合指标、历史对照、综合人物侧写与升级后的关联采样，当前新增行为见 [本地人物侧写](portrait-analysis.md)。

在抖音内打开 **设置 → DouAi → 扩展功能 → 本地数据分析**，开启记录后开始统计。默认关闭，不补录开启前的浏览记录。

统计数据保存在抖音应用私有的 `no_backup/douai-analytics/` 目录。日常记录和查看报告不会上传数据，默认不纳入配置备份；可在备份页主动选择包含分析记录，采集开关不随备份迁移。界面与图表直接在本地绘制，不加载远程脚本。只有主动点击下方的“请求 AI 分析”时，才发送所选范围的统计摘要。

## 查看报告

可选今天、近 7 天、30 天、90 天和全部保留记录。“7 天”包含今天与前 6 天，按整个范围综合分析，并保留每日趋势，不会生成七份每日报告。最多保留最近 365 个本地自然日；“全部”指当前保留的数据。报告包含浏览总次数、不同作品数、模块功能触发数、浏览趋势、作品类型占比、作者/话题/功能排行、浏览时段分布、最近记录与活跃历程。

报告使用模块统一的 Miuix 弹窗、开关、时间选择与按钮。内容区块默认显示概要，点击标题展开图表、详细记录和对应 AI 分析，再次点击可收起。浏览概览和底部 AI 请求、分享入口保持容易访问。

| 数据 | 统计口径 |
| --- | --- |
| 浏览次数 | 受支持的信息流中作品被选中；不会把请求返回或预加载绑定算成浏览。连续重复回调合并；A → B → A 计 3 次。 |
| 不同作品 | 在所选范围内按作品标识去重；本地保存哈希值用于去重。 |
| 普通图集 | 不含可识别 Live 实况照片的图片作品。 |
| 实况图集 | 含可识别 Live 实况照片的作品，整条图集只计一次；不会与普通图集重复计数。 |
| 短视频 / 长视频 | 已知时长小于 5 分钟 / 大于或等于 5 分钟；未知时长不猜测。 |
| 作者排行 | 以作品作者标识区分，显示昵称；不是账号关注关系或私聊联系人。 |
| 话题排行 | 从当前作品的元数据提取，一条作品内同名话题去重。多话题作品可贡献多个话题，因此话题次数之和可能高于浏览次数。 |
| 功能排行 | 只记录已接入统计的实际操作或功能命中，不按开关开启时长计数，也不等同于服务端执行成功。 |
| 时段分布 | 浏览发生时的本地小时，不代表观看时长。 |

图表按本地日期筛选；长范围趋势按周汇总以控制展示密度。无法可靠分类的作品单列为未知类型。直播卡片如由受支持的信息流入口识别，会与 Live 实况照片分开，不代表进入直播间或完整观看。

当前接入的功能计数包括自动点赞请求、自动关注点击、自动翻页、内容过滤生效批次、快捷菜单、视图查找器、复制文案、手势保存入口、快捷打开评论、手势倍速、评论语音提交、自动评论成功、自动回复成功、原生菜单下载任务加入和第三方下载入口。主动 AI 分析完成、打开分析分享菜单也各计为一次功能事件。排行使用各自标签，保留入口、请求、已加入任务与成功之间的差别；它们的总和表示记录到的功能事件数。

## 请求 AI 分析与分享

在“扩展功能 → AI 模型设置”添加并启用模型配置后，回到报告最下方点击“请求 AI 分析”。按钮旁说明当前模型与发送范围：所选时间范围的汇总、趋势、类型占比、作者/话题/功能 Top 10、时段分布和活跃天数。页面不会自动发起请求。

发送的是有界的统计摘要，不发送原始作品标识、媒体文件、最近记录的逐条精确时间、私聊或评论正文。请求复用当前模型的协议和全局提示词，同时附加分析任务要求；不混入测试对话或消息联系人的聊天历史。模型服务提供方会接收这次主动发送的摘要。

分析使用已保存并选中的模型配置；模型编辑页的测试对话可以使用尚未保存的草稿，修改配置后需点击“保存并启用”。测试能返回普通文本，不代表返回符合人物分析的完整 JSON 结构。若失败，页面分别提示超时、HTTP、空回复、过长或分析格式问题；LSPosed 日志的 `[analytics]` 仅包含阶段、分类、状态码、长度、结构计数和耗时，不包含正文、凭据或统计标签。

自 0.1.86 起，本地分析与测试对话、消息联系人、AI 自动回复和 AI 自动评论一样，遵循所用模型配置中的“接口协议”和“响应方式”。在模型编辑页选择“非流式”或“流式”，再“保存并启用”；已有配置未设置响应方式时默认非流式，取代 0.1.85 仅为本地 Responses 分析固定启用流式的策略。模型联系人的对话使用该联系人对应的模型配置。

同一模型配置还可选择“推理强度”，本地分析共用该选择。除“模型默认”外，界面按协议显示英文原始值：OpenAI 提供 `none/minimal/low/medium/high/xhigh/max`，Claude 提供 `low/medium/high/xhigh/max`，Gemini 提供 `minimal/low/medium/high`。这是协议候选，不代表当前模型和中转全部支持；实际能力需查服务元数据或对应模型文档，不通过向模型提问判断。旧配置默认“模型默认”，不额外发送强度参数，也不覆盖已有高级参数。强度与温度、最大输出 Token 分别设置，增加推理投入可能增加等待和 Token 消耗，不保证结论更正确。显式强度与高级参数重复设置同一个强度字段时，会在发送前提示冲突，其余嵌套参数保留。

Gemini 显式选择强度时，不能同时在高级参数中设置 `thinkingBudget`；改回“模型默认”则保留已有预算参数。

OpenAI Chat Completions、OpenAI Responses、Claude Messages 和 Gemini 均可选择流式。前两种 OpenAI 协议和 Claude 按响应方式设置 `stream`；Gemini 分别使用 `generateContent` 或 `streamGenerateContent?alt=sse`。流式只改变接收过程：模块收齐并完成校验后才显示或发送完整结果，自动回复、自动评论不会把片段发送出去；本地分析仍需通过原有图表结构和长度校验。

每次分析只提交一次 POST。流式响应在同一个连接中返回完整 JSON 时可兼容处理，不会因此再发请求；失败也不会静默切换方式或自动重试。非流式响应同样拒绝服务端明确标记为未完成的结果。选择流式时，客户端等待有总预算，迟到结果不能覆盖页面，平台仍阻塞的网络资源在有界后台清理。服务端必须支持所选响应方式，切换为流式不保证解决模型或中转超时。系统或第三方语音合成、第三方媒体解析仍遵循独立配置。[本轮设置与验证状态](release-0.1.86.md)。

发送给 AI 的统计摘要附件最多 16000 字符，并保留原有字节预算；不足以容纳时按优先级省略重复比较、矩阵和本地叙述，保留核心汇总、排行、计数、关联和采集边界并明确注明省略。压缩后仍超限会在发送前提示缩小范围。这个附件上限不代表 HTTP 504 的原因；已观察到的约 60 秒 504 位于请求返回链路。

成功后隐藏请求按钮，报告底部直接显示可选择复制的完整 AI 结果，包括侧写及各组解读；每张图表下方仍保留对应分析：浏览概览、趋势、类型占比、作者、话题、模块功能、时段分布分别显示。缺少某项数据时，分析需说明依据不足，不补造结果。模型未按完整分图结构返回时视为失败，可以重试。

区块是否收起不影响参与分析的数据。成功后概要标记“含 AI 解读”，展开区块即可阅读对应图表下方的解读；底部提供“展开各区块的 AI 解读”按钮。分享始终包含完整解读，不受收纳状态影响。

底部“分享分析文字”通过系统菜单发送时间范围、分析时间和完整解读。“导出/分享报告”可选择单张长图 PNG 或单份 A4 分页 PDF，在本地生成全部报告区块、图表、采集边界及已有 AI 结果，不会再请求 AI。尚无 AI 结果时仍可导出统计报告，并注明未生成分析。

导出使用独立的浅色纸张版式，不重新排布或展开当前屏幕；夜间模式也生成浅色报告。PNG 是一张完整长图，过长时明确提示改选 PDF；PDF 在一份文件内按 A4 分页，按正文和图表边界完整呈现，超限时提示缩小范围，不静默裁切。PDF 使用图片页面，不支持选择其中的文字，文字复制或转发仍用“分享分析文字”。

Android 10 及以上将 PNG 保存到相册 `Pictures/DouAi`，PDF 保存到 `Downloads/DouAi`，再打开系统分享；Android 9 通过系统选择器保存一个 PNG 或 PDF 文件，不再要求多图文件夹。请先核对作者、话题、最近记录和 AI 文字，后者可能引用所填自述；文件不附数据库或接口配置。打开分享面板后的完成文件会保留，取消选择接收方不会自动删除已保存文件。

请求失败保留重试入口。刷新、切换范围、清空或关闭页面会取消对应请求和未交接的导出任务，旧结果不能覆盖新范围；重新请求分析也使旧导出任务失效。已发送到服务商的请求数据无法通过关闭页面撤回，已交接给系统分享的完成文件仍保留供接收方读取，不需要时可自行删除。新版 PNG/PDF、文件提供方与接收应用的验证仍待本轮结果，见 [0.2.4 本地记录](release-0.2.4.md)。

结果仅在当前报告页面会话保留。刷新图表、切换范围或重新打开页面后需要重新点击分析，避免旧结论对应更新后的图表。分析应把内容偏好和使用节律的统计依据与不确定推测分开，不能代替对使用者真实身份、健康状况或完整生活的了解。

不必每天点击分析。忘记当天请求时，之后仍可选择包含那一天的 7 天、30 天、90 天或全部范围，再主动生成分析；不会自动补发请求。目前不支持单独选择某个历史日期。越早的记录可能已按保留期限删除关联明细或汇总，无法补回已删除的数据。

## 停止记录与清空

关闭记录立即停止接收新统计，已有记录仍可查看。清空操作需在页面确认；清空前排队的旧事件不会在清空后重新写入。清空后继续开启记录，则后续浏览重新累计。

卸载或清理抖音应用数据也会删除统计；卸载 DouAi 本身不会清理抖音私有目录中的数据。首次使用日期表示本地统计首次收到事件的日期，不代表安装模块日期。

## 数据边界

在“扩展功能 → 配置备份”中，“包含本地分析数据”默认不勾选。选中后，备份会包含当前保留的统计、浏览与操作关联、作者和话题、自述与反馈，写入使用者选择的本地文件；不包含采集开关、临时 AI 解读或媒体文件。文件不会自动发送给模型。

导入时先预览。只有另行勾选“恢复本地分析数据”并确认，才会替换当前分析记录，自述与反馈也一并恢复；配置合并/覆盖与分析恢复独立。未勾选、普通配置备份或旧版备份均不改动分析记录。恢复不会自动开启采集，恢复的数据仍受保留期限约束。普通配置上限 2 MiB，含分析备份上限 32 MiB；超限会失败，不会静默裁剪成不完整备份。

本功能记录作品类别、作者、话题、浏览时间与已接入功能的事件。日常统计不会读取媒体文件、保存作品正文、采集私聊/评论内容或调用网络接口；主动 AI 分析的发送范围见上一节。数据库使用异步单线程写入，查询在后台完成，待写队列上限为 256 项；极端高频导致队列满时会丢弃新增统计，避免阻塞宿主。数据保存于应用沙箱，并非额外加密数据库。

当前采集面向抖音 40.6.0 已适配的视频与图集信息流回调。搜索、个人主页、直播间及其他特殊容器是否复用这些回调，需要真实宿主验证。统计不包含开启前、模块未生效时或未覆盖入口中的行为。

代码与验证入口：`analytics/LocalAnalytics.java` 管理本地数据，`feature/LocalAnalyticsHook.java` 接入作品选中回调，`ui/LocalAnalyticsDialog.java` 展示报告。0.1.86 的 215 项定向检查和 169 个套件、1625 项完整回归全部通过，0 失败、0 错误、0 跳过；最终 APK 的 3 项契约检查已执行通过，Release 构建、签名与归档核对通过。真实模型、中转和真机行为仍待实测，未远端发布。详细结果见 [0.1.86 本地交付记录](release-0.1.86.md)，初版统计口径的历史验证见 [0.1.80 记录](release-0.1.80.md)。
