## 结论与使用行为

自动评论使用自己的浮窗；私聊、群聊、评论自动回复共用回复浮窗。两者独立创建、分别保存拖动位置，并相互避让。显示条件独立，关闭或没有回复任务时只移除回复浮窗；Activity 暂停和模块关闭会移除两者。

评论自动回复由“开启自动回复”和“接收评论回复”共同控制，悬浮窗使用“自动回复 → 发送与记录 → 悬浮提示”（`reply_tip`）。存在任务时，从等待、素材读取、AI 生成、语音合成到发送预览持续更新同一回复浮窗。没有待处理任务时不常驻。

## 调用路径与判别

P-1：通知解析 → 校验评论与当前账号、原评论的关联 → 去重/额度/持久认领 → `CommentReplyHook.preparation` → `AutomationDispatcher.trackReply` → 回复浮窗。

E-2/E-3 支持 F-1：这段日志的问题发生在回复任务准入之前。`NativeCommentReplyInbox` 在缺少 parent/root、且无法从指向本人和本人一级评论恢复上下文时跳过该通知；不能仅凭收到一条评论通知就断定应自动回复。现有材料不足以区分这些通知本来不属于回复本人的评论，还是宿主返回了缺失的关联数据。

P-2：自动评论与自动回复各自更新 `CommentRingOverlay`，使用不同 View 和位置键，挂载在同一 Activity decor 时调用 `avoidOverlap`。没有自动评论显示就关闭回复浮窗的分支。

E-1/E-2 不能支持“两个已显示浮窗发生抢占”的结论。若实际新回复任务已进入生成/发送，但界面仍看不到，需要进一步关联 `show_requested` 与 `attached/shown/parent_match`；这些 View 状态为 true 仍不能排除更高层 Dialog/PopupWindow 的遮挡。
