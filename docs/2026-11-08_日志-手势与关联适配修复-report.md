# 抖音 41.0.0 手势失效与关联字段适配修复

2026-11-08，分析用户提供的 `LSPosed_20261108_083108.zip`。范围为工作区 DouAi 的本地日志排查、原 APK 对照、修复与签名构建；没有操作手机或发布远端。

## 结论

上一版 41.0.0 适配漏掉了规则表之外的反射字段。242 条规则唯一匹配只能定位声明的类与方法，无法证明这些额外字段仍满足消费者要求。手势初始化因此在注册入口前退出，自动播放也被同一类型校验拒绝。

本轮修复视频参数字段、四项个人资料数字映射，并补充行为回归和原始 APK 合同。40.6.0、40.8.0 继续使用原字段，持续倍速、触摸事件交回及语音重试/文本回退策略保持原有行为。最终安装包及其独立验收见 [0.2.41 构建记录](release-0.2.41.md)。

## Evidence → Finding → Path

### E-001 当前安装失败

0.2.40 三次启动中，自动播放各出现一次 `IllegalStateException`；其旧日志包装重复不算独立故障。最新事件在 `archive/log/modules_2026-11-08T08_30_17.709147.log:154`，按匹配 R8 mapping 还原至 `AutoPlayHook.java:157` 的参数关系检查。

最新手势状态在同文件第 373 行：`enabled=true`、`hook_state=not_installed`。日志没有给出可独立还原的手势安装栈；此项根因由实际未安装状态、原始字段类型和安装失败行为回归共同确认。41.0.0 原 Smali 的 `VideoViewHolder.A2` 是 `QPlayVM`，`B2` 才是 `VideoItemParams`；根视图 `w` 和 `mFeedContext` 关系仍正确。

### F-001 视频参数字段迁移未进入消费者

**确认度：高，日志、原 DEX 与失败回归相互印证。** `FeedGestureToolsHook` 和 `AutoPlayHook` 把旧 `A2` 当作 `VideoItemParams`，触发其严格类型检查。`LocalAnalyticsHook` 也有两处同样的旧读取，导致用于拒绝邻居视频的 panel 校验失效；该统计问题由本地行为回归复现，不能把日志中所有统计警告都归因于它。

**P-001 调用路径：** 原 APK Profile → `HostResourceProfile.feedItemParamsField` → 41 使用 `B2`、旧版使用 `A2` → 三个消费者读取相同参数对象 → 继续原有类型、panel 及当前 holder 检查。保留原类型校验，没有靠放宽检查让安装通过。

### E-002 个人资料统计字段

当前三次启动各有一次 `spoof_profile` 安装回滚；最新事件在同日志第 266 行，R8 还原至 `ProfileSpoofHook.java:69`。采集时该功能关闭，但模块仍尝试注册并遇到错误。

41.0.0 原 `PandaHeaderValueArea` 及 `X/1EJP` 的数据写入路径确认：

| 语义 | 40.6/40.8 | 41.0.0 | 41 原始数据来源 |
| --- | --- | --- | --- |
| 获赞 | `y` | `x` | `totalFavoritedStr` |
| 关注 | `w` | `v` | `User.getFollowingCount()` |
| 粉丝 | `x` | `w` | fans/follower helper |
| 朋友/互关 | `F` | `E` | `updateHomepageCount` 路径 |

新包的 `y` 是“获赞”标签，`F` 是 `LX/1EMy` 状态对象；只替换 `F` 仍会错写其他数字及标签。

### F-002 四项统计必须整体按版本选择

**确认度：高，匹配栈和原 DEX 语义一致。** `ProfileSpoofHook` 按当前 Profile 使用 `x,v,w,E` 或旧 `y,w,x,F`，继续要求计数字段是 `TextView`，且只修改当前用户的本地显示。

**P-002 调用路径：** 资料 render 回调 → 检查是否本人 → 读取四项语义计数视图 → 按配置改本地文本 → 切换他人、关闭功能或关闭 Hook 时恢复原文本。回归同时保护 `y` 标签不被改写。
