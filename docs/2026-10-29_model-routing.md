# AI 模型保存、功能选择与快捷切换

2026-10-29，针对独立模型选择、快捷切换后自动评论中断及模型管理“启用”含义进行修复。本轮保持现有供应商配置格式、请求协议、提示词与语音处理，按功能选择实际模型。

## 配置与功能的关系

模型配置是保存的接口、密钥、模型、流式方式与请求参数集合，没有逐配置的 enabled 字段。旧界面“已启用”表示 `activeId` 指定的全局默认，并不禁止自动回复、自动评论或分析使用其他已保存配置。

| 功能 | 选择方式 | 影响范围 |
| --- | --- | --- |
| 全局默认 | `ai_model_settings_v2.activeId` | 跟随全局的功能及使用全局配置的测试入口 |
| 自动回复 | `reply_model_id` | 私聊、群聊和评论自动回复共用 |
| 自动评论 | `comment_model_id` | 自动评论独立选择 |
| 本地数据分析 | `analytics_model_id` | 分析独立选择 |

后三项选择空字符串表示跟随全局默认；明确选择已保存配置时，不要求全局已有选择。绑定的配置被删除后仍要求重新选择，保持原来的失败行为，不自动换供应商。

按用户要求，模型管理页只添加、编辑、保存和删除配置。保存不改变全局默认或任何功能绑定。快捷“切换模型”先选择上述功能，再选择配置；后三项提供“跟随全局默认”，每次只写所选功能。

## 误取消问题及修复

旧快捷菜单只写全局 `activeId`，但三个自动化 Hook 都按整个模型集合的序列化字符串变化取消任务。因此即使自动评论固定选择 C，仅把全局 A 切成 B，也会递增评论任务代数、取消 C 的请求并清理队列。

实际红例通过三个本地 MockWebServer 驱动自动评论：C 的流式请求已到达服务端，暂缓返回；全局 A 切成 B，C 的绑定不变。修改前任务代数从 1 变成 2，断言失败。另两个 UI 红例分别捕获“保存新配置顺便激活”及“快捷菜单没有功能选择层”。3 项均为实际断言失败，见 `work/ai-model-routing-20261029/repro-before-results/`；较早编译错误日志单独保留，不计入业务红例。

修复路径为 `AiModelSettings.sameAutomationSelection` → 三个自动化 Hook 的配置刷新。比较功能绑定策略及最终选中的完整配置；全局默认和其他配置改变时，显式绑定不变的功能继续运行。改变本功能绑定、编辑其选中配置或使配置无效时，仍使用原有取消逻辑。无效配置仅作保守原值比较，不隐藏正常请求时的配置错误。
